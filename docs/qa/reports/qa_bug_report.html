Section 1: Detailed Bug Reports & Verified Fixes
Bug ID: 001
High Severity Resolved
Title: Create artist profile is taking longer to complete
Description: The Create Artist Profile process takes an unusually long time to complete after the user submits the profile. The delay impacts on the overall user experience and may give the impression that the application is not responding. This behavior can be seen few times.
Steps to Reproduce:
  1. Navigate to Artist Registration.
  2. Enter all required artist profile details.
  3. Click Create Artist Profile.
  4. Observe the time taken for the profile creation to complete.
Actual Result: The artist profile creation process takes longer than expected to complete, and the submit button displays an indefinite spinning indicator without progress state.
Expected Result: The artist profile should be created within a reasonable amount of time, with an appropriate loading indicator displayed while the request is being processed.
Figure 1.1: Submit button in prolonged loading state during artist profile submission.
Technical Resolution: Implemented database schema versioning in api.php (SCHEMA_VERSION = 9) to eliminate redundant, blocking ALTER TABLE column inspections on every request. Client-side timeout and progressive indicator added to prevent indefinite hang.
◀ الترجمة العربية للمشكلة:
العنوان: عملية إنشاء الملف التعريفي للفنان تستغرق وقتاً طويلاً للاكتمال.
الوصف: عند النقر على "إنشاء ملف الفنان"، تتأخر الاستجابة بصورة غير معتادة مما يوحي بتجمد التطبيق. تم الحل عبر تسريع استعلامات قاعدة البيانات وتفادي الفحص المتكرر للجداول.
Bug ID: 002
High Severity Resolved
Title: Phone number field accepts alphabetic and special characters in Edit Artist Profile
Description: In the Edit Artist Profile section, the phone number field allows users to enter alphabetic characters and other invalid characters. The field should restrict input to a valid phone number format.
Steps to Reproduce:
  1. Navigate to Artist Profile.
  2. Locate the Phone Number field.
  3. Enter alphabetic characters or invalid special characters (e.g. +971 sjkhfskn).
  4. Observe the phone number field.
Actual Result: The phone number field accepts alphabetic and invalid characters and saves them directly to the database.
Expected Result: The phone number field should accept only valid numeric input according to the supported phone number format and display a validation message for invalid input.
Figure 2.1: Phone number field allowing alphabetic characters "+971 sjkhfskn".
Technical Resolution: Added FilteringTextInputFormatter.digitsOnly and LengthLimitingTextInputFormatter(15) to the phone number text fields, coupled with a strict regex validator (r'^\+?[0-9]{7,15}$') on both frontend and backend.
◀ الترجمة العربية للمشكلة:
العنوان: حقل رقم الهاتف يقبل الحروف الأبجدية والرموز غير الصالحة في شاشة تعديل الملف.
الوصف: يقبل الحقل إدخال نصوص مثل "+971 sjkhfskn". تم الحل بإضافة حظر إدخال أي حروف غير رقمية مع تحديد حد أقصى والتحقق من صحة الرقم قبل الحفظ.
Bug ID: 003
Medium Severity Resolved
Title: Edit/delete option is not available in Photo Gallery after viewing an Artist profile
Description: In the Artist tab, after navigating to View Profile, the Photo Gallery does not provide an Edit/delete option for the uploaded/updated photos.
Steps to Reproduce:
  1. Navigate to the Artist tab.
  2. Click on View Profile for an artist.
  3. Navigate to the Photo Gallery section.
  4. Update or upload a photo.
  5. Check the available options for the photo.
Actual Result: The Edit/delete option is not available for the photo in the Photo Gallery, leaving users unable to curate or remove obsolete pictures.
Expected Result: An Edit/delete option should be available for the uploaded photo so that the user can modify or replace it when required.
Figure 3.1: Photo gallery list displaying artwork cards without edit or delete actions.
Technical Resolution: Integrated an action overlay menu (Edit title, replace image, and delete item) for authenticated gallery owners, bound to the backend delete_gallery and update_gallery API endpoints.
◀ الترجمة العربية للمشكلة:
العنوان: خيار التعديل أو الحذف غير متاح في معرض الصور بعد عرض الملف التعريفي.
الوصف: لا يستطيع الفنان إزالة أو تعديل الأعمال الفنية والصور بعد رفعها. تم الحل بإضافة أزرار التعديل والحذف وتأكيد الحذف بصورة آمنة.
Bug ID: 004
Critical Severity Resolved
Title: Single dot (.) displayed instead of Arabic translation for Event & Artwork details
Description: When switching the application language to Arabic, dynamic fields (such as event descriptions, titles, categories, and tags) containing words like "Test", "Tezt", or "Testing" were translated and displayed as a solitary period (.) instead of proper Arabic text.
Steps to Reproduce:
  1. Create or open an Event with title/description containing "Test" or "Tezt" in English.
  2. Switch the language toggle at the top header from English to Arabic (عربي).
  3. Navigate to the Event Details page.
  4. Inspect the "حول هذه الفعالية" (About this event) card and section titles.
Actual Result: The card displays only "." under "حول هذه الفعالية", completely wiping out the readable content and corrupting the cached translation table.
Expected Result: The system should accurately translate "Test" to "اختبار" or retain the original English text if no valid translation candidate exists, never outputting punctuation marks.
Figure 4.1: Side-by-side comparison — English text "Test" (left) erroneously transformed into "." in Arabic (right).
Technical Resolution: Fixed in both api.php and data_translator.dart: Added dictionary mappings for test, testing, tezt, demo, sample; built isValidTranslationCandidate() to reject translations consisting solely of punctuation; added fallback loop through MyMemory matches; purged corrupted dot entries from translations_cache; added model-level defensive fallback in ArtEventModel.
◀ الترجمة العربية للمشكلة:
العنوان: ظهور نقطة واحدة (.) بدلاً من النص العربي المترجم في تفاصيل الفعالية والأعمال الفنية.
الوصف: عند التحويل للغة العربية، تظهر نقطة بدلاً من ترجمة الكلمات مثل "Test". تم إصلاح الخلل بالكامل في الخادم والتطبيق وربط القاموس العربي ("اختبار") مع تنظيف الذاكرة المؤقتة.
Bug ID: 005
Medium Severity Resolved
Title: Home screen bottom grid text overflows card boundary on smaller screens
Description: On mobile viewports, the card title "GALLERIES | ART CENTERS REGISTRATION" overflows or overlaps the bottom container edge, causing awkward text clipping and visual disharmony.
Steps to Reproduce:
  1. Launch the application on standard mobile screen sizes.
  2. Scroll to the bottom of the Home screen grid.
  3. Observe the eighth card label: "GALLERIES | ART CENTERS REGISTRATION".
Actual Result: The multi-line text clips into the card boundary and obscures the red subtitle underline.
Expected Result: Card text should adapt flexibly with dynamic font scaling, auto-wrapping, or concise labels (e.g. "Gallery Registration").
Figure 5.1: Text overflow on the bottom right dashboard tile.
Technical Resolution: Applied FittedBox and maxLines: 2 with TextOverflow.ellipsis on all dashboard grid labels, ensuring crisp rendering across all screen densities.
◀ الترجمة العربية للمشكلة:
العنوان: خروج نص البطاقة الأخيرة عن حدود المربع في الشاشة الرئيسية.
الوصف: يمتد نص "GALLERIES | ART CENTERS REGISTRATION" خارج حدود البطاقة. تم ضبط حجم الخط التلقائي ومنع تجاوز النصوص للحدود.
Bug ID: 006 • Event Date Selection Inversion
Medium Severity Resolved
Description: When creating or filtering events, the date picker allows the user to select an End Date earlier than the Start Date without inline validation warning.
Resolution: Constrained firstDate of the End Date picker to the selected startDate and added cross-field validator check before submission.
Bug ID: 007 • Ticket Quantity Negative / Zero Input
Medium Severity Resolved
Description: The ticket purchase modal allowed manual keypad entry of zero or negative ticket quantities, which disrupted total price calculations.
Resolution: Enforced lower bound clamping (quantity = Math.max(1, input)) and disabled the minus button when quantity equals 1.
Bug ID: 008 • ETag HTTP Stale Cache on New Entity Creation
High Severity Resolved
Description: With backend Cache-Control: public, max-age=60 and ETag matching enabled, newly created galleries or events did not immediately appear when redirecting to the list view within 60 seconds.
Resolution: Updated API client to append a timestamp cache buster (_t=timestamp) or send Cache-Control: no-cache immediately upon completing a POST/PUT/DELETE mutation.
Section 2: UI / UX Improvement Suggestions
UI Improvement Suggestion 01: Information Architecture & Dashboard Reordering
Suggestion: Reorder the home dashboard sections based on user relevance and frequency of usage.
Recommendation:
  • Place the most frequently used features at the top: Promote Artists, Events & Competitions, and Galleries to the primary upper quadrant for immediate 1-tap access.
  • Move the About Us section to the last position: About Us is static, informational content and is rarely visited repeatedly by active community members.
Expected Benefit: Significantly reduces cognitive friction, decreases clicks-to-content, and boosts user engagement with primary platform activities.
Figure 6.1: Current layout with "About Us" in top-left position versus recommended task-oriented hierarchy.
◀ مقترح تحسين الواجهة (باللغة العربية):
المقترح: إعادة ترتيب أقسام الشاشة الرئيسية وفقاً لمعدل وأهمية الاستخدام.
التوصيات: وضع أقسام الفعاليات والفنانين والمعارض في الصدارة في أعلى الشاشة، ونقل قسم "من نحن" (About Us) إلى نهاية القائمة لأنه محتوى تعريفي نادراً ما يحتاجه المستخدم المتكرر.
UI Improvement Suggestion 02: Explicit Media Management Controls
Suggestion: Add quick contextual hover/tap action icons (Edit Title, Replace Image, Delete) on all photo gallery cards.
Recommendation:
  • Add a 3-dot overflow menu or top-right action badges on each artwork card.
  • Provide a confirmation modal before permanently deleting images to prevent accidental data loss.
Expected Benefit: Empowers artists and gallery curators with direct autonomy over their creative portfolios without navigating complex administrative screens.
UI Improvement Suggestion 03: Real-Time Input Masking & Inline Validation
Suggestion: Adopt proactive input formatters on phone number and pricing fields across all forms.
Recommendation:
  • Auto-format international dial codes (e.g., +971 50 XXX XXXX).
  • Display green checkmarks when valid and clear red warning captions for invalid inputs before the submit button is clicked.
Expected Benefit: Eliminates bad data entry at the source, guarantees database hygiene, and streamlines profile submission.
